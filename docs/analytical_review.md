# Sceptical analytical review

Reviewed 13 November 2026 against source responses, local database outputs, independent fixture expectations and rendered figures. This review records corrections and limits, not a blanket assertion that everything passed.

| Issue found | Why it matters | Resolution / remaining limit |
|---|---|---|
| Official website describes an older trip schema and subminute removal | Blindly copying documentation would misname identifiers and exclusions | Inspected actual archive first. Enforce current 13-field header. Retain and audit 43,033 positive subminute rentals (2.15% of eligible cohort); do not invent a missing bike/person identifier |
| Archive month differs from actual start month on 213 source rows | Initial source-month equality rule would discard valid within-period rentals | Audited start/end/source month combinations; changed cohort to actual start month in the loaded month set. Recovered 38 eligible August-start rentals from September file; added a boundary fixture. Source-month counts remain provenance. Publisher boundary convention differs across archives; no claim of complete real-world rental coverage |
| Three October-start records end in the ambiguous November DST hour | August–October start dates alone do not remove DST ambiguity | Roundtrip detection covers both endpoints; these records are excluded rather than assigned invented offsets |
| UTC assertions initially inherited the host's Europe/London session display | A correct instant can appear one hour different when extracting a session-local hour | Set dbt/report sessions to UTC and make fixture assertions explicitly UTC. Verify New York summer/winter offsets plus spring/autumn edge cases |
| 1,115 raw durations exceed 24h, including one overlapping DST flag | Summing overlapping diagnostic flags would overstate excluded rows | Mutually exclusive quality waterfall: 1,114 invalid durations, 148 outside the actual analysis period, 3 unresolved DST = 1,265 excluded rows; 2,000,497 − 1,265 = 1,999,232. Raw diagnostic counts are labelled as overlapping |
| Missing endpoints are substantial and concentrated in electric-bike records | Dropping incomplete rows globally would change volumes and mix | 290,065 missing starts, 305,363 missing ends retained in aggregate cohort. Direction-specific station denominators are restricted. Missingness is not assumed random or attributed to rack parking without evidence |
| Trip codes differ from GBFS station IDs | A direct join would lose observations or mis-map stations | Match current short_name only, enforce uniqueness and report unmatched code/trip counts. Do not use current capacity as historical capacity |
| Duplicate handling could conceal conflicting ride records | Arbitrary deduplication can manufacture a single clean fact | Audit duplicate IDs and conflicting analytical attributes before publishing. Both are zero in selected real files; fixture verifies duplicates do not multiply facts. Conflicting records abort report |
| Counts and net flows are not failed-attempt measures | Attractive station rankings can overclaim unmet demand | Candidate chart says investigation, uses completed departures, and shows window sensitivity. Eight of ten core candidates overlap with wider windows. No stockout ranking or causal station comparison |
| Successful HTTP retrieval can contain stale source reports | Fresh network response is not fresh station information | Check station and feed clocks, cap state by both plus hold/next retrieval. Future timestamps are invalid. Preserve raw clocks and compute age diagnostics |
| Closures, staleness and gaps require different denominators | Counting all zeros as failures or all missing periods as success corrupts availability | Closure support is bounded and removed from expected eligibility; unknown time stays in denominator of coverage. Closed and unobserved availability is undefined, never a success or stockout. Separate departure and arrival flags |
| Long gaps can silently generate hours of carried-forward state | Dense early polling can mask later outages | Half-open intervals expire by freshness and 180s hold; tests verify irregular intervals, gaps, stale and closed stations, missing vehicle types and duplicate snapshots |
| Time weighting, station weighting and served-trip weighting answer different questions | Different denominators can reverse priority rankings | Known weighted fixture yields .9 time-weighted, .5 equal-station and .25 under explicit 1:3 station weights. Pilot reports equal/time summaries with coverage, not total-demand weighting |
| Tiny live sample cannot support stable availability conclusions | Snapshot count overstates independent evidence | Two snapshots, 95-second horizon, no station confidence intervals or reliability plot. Report is technical and descriptive; future station-day/window analysis is explicitly deferred |
| Binomial confidence intervals on every snapshot would be false precision | Repeated measurements and common weather/operations create dependence | Fixed-period descriptive summaries now. Proposed joint weekly day blocks for future panel ratios; demonstration helper refuses short histories and has an explicitly different equal-day target |
| User-level trial power does not solve station-network interference | Suggested alternatives move scarce bikes and docks across arms | Limit initial own-assignment estimand to trial saturation. Field uncertainty/design gate remains open; a cluster trial needs cluster variance, count and power before launch |
| Missing, immature or engagement-conditioned experiment outcomes can bias findings | A seemingly positive result may be selection, not treatment | ITT and first-intent design; mature time-based cohorts; ledger reconciliation; missingness bounds proposed. Synthetic scenarios expose biased complete-case and immature-as-failure analyses |
| Repeated-intent independence inflates false positives | More rows do not equal more independent users | Synthetic null stress test: 11.35% naive rejection versus 4.7% user means, with MC SE. Primary trial uses first intent; repeated outcomes need account-level uncertainty |
| Several SQL aliases collided with reserved words; dbt default database path was wrong | Code that looks plausible can fail at integration | Explicit aliases, non-reserved status columns, repository-root database profile. Actual three-model dbt build and offline fixture build run successfully |
| Test subprocess originally assumed dbt on shell PATH | A reviewer invoking .venv/bin/pytest could fail despite installed dependencies | Resolve dbt beside the running Python interpreter; actual offline integration test passes |
| Candidate chart footer initially overlapped the x-axis label | Correct numbers can still be hard to interpret | Moved report footnotes below labels and re-rendered; all six exported figures visually inspected |
| Locally generated dbt user identifier appeared in initial implementation commit | Machine state does not belong in a portable project | Removed from current tree and ignored. It is a generated UUID, not an authentication secret. No raw data, tokens or databases are committed |

## Verification evidence and limits

`bash scripts/validate.sh` checks lint, 23 offline fixture/integration tests, Python compilation, aggregate output consistency and readable figure files. Fixtures cover always available/empty, irregular intervals, long gaps, stale and future reports, closures, duplicates, absent stations, vehicle-type uncertainty, thresholds, both DST transitions, known weighting, archive-boundary attribution, idempotent trip ingestion and collector persistence/failure logging and the persistent TTL scheduling floor. Experiment interval arithmetic matches independent formulas and statsmodels. The real-data dbt build has three models and eight passing data tests. The simulation has 2,000 repetitions in each of nine scenarios, with MC uncertainty rather than exact nominal-rate demands.

GitHub CI passed on Linux/Python 3.11 for reviewed implementation commit 2487416 ([run](https://github.com/stephanieboyle/bikeshare-product-analytics/actions/runs/43404163212)); local validation used macOS/Python 3.10.6. CI installs the frozen dependency graph then executes credential-free checks with synthetic fixtures and committed aggregates. It does not recollect live data or redistribute raw trips. Prospective reruns produce new evidence, not a replay of the same historical state. Source revisions can change hashes and findings. Full GBFS schema conformance, operational service uptime, field tracking and network-interference inference are not certified by these tests.

Remaining analytical work: sustained prospective observation; daily/window splitting; mature coverage/ranking/weighting and coarser-interval sensitivities; nearby-alternative feasibility; credible future-period uncertainty; current-app audit and rider research; operator-side A/A tracking pilot; field-design calibration. These are evidence gates, not hidden completed deliverables.
